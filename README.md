# Музейный 3D-каталог — офисный сервер

Текущий каталог упакован для Docker без изменения геометрии и 8K-текстур. Модели, фотографии и метаданные хранятся в `./data`, отдельно от Git и образа. Ручной импорт; автоматического сканирования папок нет.

## Запуск на Linux

Нужны Docker Engine и Docker Compose v2. Архив `catalog-data-20261103.zip` передаётся отдельно от Git. В нём — текущие 29 видимых моделей с прежними UUID, метаданные, индекс залов и фотографии/превью. Старые скрытые варианты и нативные рабочие сцены в перенос не включены, исходные данные на рабочем ПК сохранены.

```sh
git clone https://github.com/FantomPie/bansai_git.git
cd bansai_git
cp .env.example .env
unzip /path/to/catalog-data-20261103.zip -d .
sudo chown -R 1000:1000 data
docker compose config --quiet
docker compose build --pull
docker compose run --rm --no-deps catalog node scripts/verify-data.mjs /data
docker compose up -d
curl -f http://127.0.0.1:8080/healthz
```

Образ запускается непривилегированным UID 1000. Сначала распакуйте архив и назначьте права; иначе контейнер не сможет создать `models` в томе. Проверка данных сверяет размеры и SHA-256 каждого файла.

По умолчанию сайт доступен на самом сервере: `http://127.0.0.1:8080/`. Для просмотра по локальной сети установите в `.env` `BIND_ADDRESS=0.0.0.0` и откройте `http://IP_СЕРВЕРА:8080/`. Публикуя наружу, используйте существующий reverse proxy офиса с HTTPS. Загрузка GLB должна передаваться потоково, с поддержкой Range; не ставьте перед файлами маленький лимит ответа или короткий таймаут.

Пример location для существующего Nginx на том же хосте:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_read_timeout 600s;
}
```

TLS и домен настраиваются в офисном proxy; сертификаты и ключи в репозиторий не кладутся. Если proxy сам работает в Docker, подключите его к сети этого compose и направьте на `catalog:3000`, либо используйте корректный адрес хоста. Внешний посетитель должен получать трафик от офисного сервера, не через старый туннель рабочего ПК.

## Сжатие без потери качества

После восстановления данных можно один раз подготовить `.glb.gz`:

```sh
docker compose exec catalog node scripts/compress-models.mjs /data
```

Сервер автоматически использует свежую `.gz` при поддержке gzip браузером. Оригинальные GLB остаются неизменными. Range-запросы обслуживаются по оригиналу. При замене GLB пересоздайте его `.gz`; старый сжатый файл автоматически не используется, если он старее оригинала.

## Загрузка новых моделей

### Публикация на bansai.duckdns.org через GitHub

Офисный сервер опрашивает `FantomPie/bansai_git` раз в 5 минут. Код публикуется в `main`; сервер пересобирает контейнер, проверяет доступность и при ошибке откатывает код.

Единственный источник структуры — `catalog/catalog-index.json` в репозитории. Поля: `updatedAt`, `objects`, `folders`, `tzGroups`, `tzSource`; без `models`. У объектов обязательны уникальные непустые `path` и непустые `name`. Сначала закоммитьте структуру и дождитесь появления пути в `/api/catalog`. Локальные изменения индекса на сервере будут перезаписаны.

Затем публикуйте GitHub Release с `NAME.glb`, одноимённым `NAME.json` и фотографиями из его `photos`. Sidecar содержит `name`, `folder`, `placement`, `photos: [{file, caption}]`, при необходимости `viewerDefaults`. `folder` должен дословно совпасть с существующим `objects[].path`, иначе импорт получит 400. GLB 2.0 содержит встроенные текстуры; лимит Release — 2 ГБ на файл. Сервер сам создаёт фото `_thumb` (320 px) и `_view` (1600 px). Модели, фото и `data/` не коммитятся. SSH и ручной деплой для этого канала не используются.

### Локальный административный интерфейс для самостоятельного размещения

По умолчанию загрузка выключена, сайт работает на просмотр. Для владельца: задайте новый случайный `UPLOAD_TOKEN` в локальном `.env`, установите `ENABLE_ADMIN=true`, затем `docker compose up -d --force-recreate`. Административный интерфейс доступен только через порт хоста `127.0.0.1:8081`. Не проксируйте его наружу. С другого компьютера используйте SSH-forwarding:

```sh
ssh -L 8081:127.0.0.1:8081 user@office-server
```

Затем откройте `http://127.0.0.1:8081/`. Токен вводится в форме загрузки. Внешний порт 8080 не принимает загрузки даже с токеном. Старый токен рабочего ПК не переносился.

## Обновление, резервная копия и перенос ссылок

### Правки под изображениями доспеха

На `/armor/` под открытым изображением можно отправлять общие правки с необязательным именем. Они привязаны к детали, версии и ракурсу, хранятся в `data/armor-comments/*.jsonl` и не перезаписываются из Git. Включайте эту папку в резервную копию данных. Обновление контейнера комментарии сохраняет. Текст отображается как обычный текст, лимит 4000 символов; отправка принимается со страницы сайта и ограничена по частоте. Имена указываются самими авторами; отдельного входа в аккаунт нет. Правки не меняют статус приёмки детали.

Внешний reverse proxy должен пропускать `GET` и `POST` ровно для `/api/armor/comments` (JSON, до 16 КиБ), сохраняя исходные `Host` и `Origin`. Если перед приложением установлен общий запрет методов записи, добавьте точечное исключение; другие API и административный порт открывать не нужно. Приложение само обрабатывает этот endpoint на публичном порту 3000. Настройки внешнего proxy не входят в данный репозиторий. Диагностика: POST с JSON `{}` к этому endpoint должен вернуть JSON с HTTP 400 «Деталь не найдена»; пустой HTTP 405 означает, что запрос отклонён до обработчика приложения. После разрешения проверьте реальную отправку из формы, перечитывание с другого браузера и сохранение после обновления контейнера.

`docker compose down` не удаляет `./data`. Перед обновлением копируйте всю папку `data` и `.env` в резервное хранилище вне Git; затем `git pull && docker compose up -d --build`. Откат кода — checkout прежнего коммита и rebuild; резервную копию данных восстанавливайте отдельно. Не очищайте тома командой удаления данных.

Ссылки `/?model=UUID` сохраняют тот же UUID. Сам домен `*.ts.net` принадлежит Tailscale и автоматически на офисный сервер не переносится: техгай должен сообщить новый адрес/домен. До проверки нового сервера текущий сайт и туннель остаются включены. После запуска проверьте с внешнего компьютера без VPN:

```sh
curl -I -H 'Range: bytes=0-1023' 'https://ВАШ-ДОМЕН/models/0a1c1a54-c65e-4ef2-916a-46bcba992548.glb'
curl -I -H 'Accept-Encoding: gzip' 'https://ВАШ-ДОМЕН/models/0a1c1a54-c65e-4ef2-916a-46bcba992548.glb'
```

Первый ответ: 206 и Content-Range. Второй после подготовки сжатия: Content-Encoding gzip. В браузере откройте Бранденбург, самурая, русский и нюрнбергский доспехи; проверьте вращение, Clay, фото и вкладку Network. Локальный тест не является проверкой пропускной способности офисного интернет-канала.

## Состав и ограничения

Сервер — Node.js 22, сторонних серверных npm-зависимостей нет. Основная библиотека просмотрщика лежит локально. Опциональный HDR «Утренний свет» использует внешний URL; нейтральная студия работает без него. Файлы `.local`, ключи, Windows-сервисы и пути рабочей машины в образ не включены. Служба использует только HTTP; размещайте публичную версию за HTTPS proxy.

Проверки сборки записаны в `VALIDATION.md`. Фактический Docker build необходимо проверить на хосте с Docker; на машине подготовки Docker отсутствует.
